# Инструкция для агента

Это репозиторий книги «Сети с нуля». Книгу пишут агенты ИИ, а автор
проекта читает её как главный читатель-новичок и сообщает, что непонятно.

## Что прочитать в начале каждой сессии (по порядку)

1. `README.md` — что это за проект, коротко.
2. `DECISIONS.md` — все принятые решения и почему. Не пересматривай их
   без запроса автора.
3. `RULES.md` — правила книги. Это главный документ, он важнее всего
   остального, кроме прямых слов автора.
4. `PLAN.md` — оглавление. Источник правды по структуре.
5. `WORKFLOW.md` — как пишется и проверяется каждая подглава.
6. `CONVENTIONS.md` — имена файлов, шапки, реестр терминов.

Потом выполни `python3 tools/book.py status`, чтобы увидеть, что готово
и что дальше.

## Жёсткие правила (кратко, полностью — в RULES.md)

- Аббревиатура при КАЖДОМ упоминании идёт с расшифровкой в скобках:
  английский оригинал и перевод. Исключение: повтор в том же абзаце.
- Никаких аналогий с почтой, письмами, разговором людей, дорогами.
- Каждое понятие объясняется через то, чем оно является физически,
  и вводится ДО первого использования.
- Простой язык. Сложное становится простым за счёт контекста.
- Термин, которого нет в `terms/terms.yaml`, нельзя использовать
  в тексте, пока он не добавлен туда с указанием, где введён.
- Протоколы VPN и обхода: подробно только новые принципы маскировки,
  остальное абзацем. Версии и параметры — только в практикуме.

## Команды

```
python3 tools/book.py status          # статусы всех подглав
python3 tools/book.py check           # проверка терминов во всех готовых текстах
python3 tools/book.py check 11.4      # проверка одной подглавы
python3 tools/book.py next            # следующая подглава для работы
python3 tools/book.py scaffold        # создать файлы по PLAN.md (не перезаписывает)
```

## Автор проекта

- Он же главный читатель: знает компьютер на уровне пользователя,
  в сетях с нуля. Его вопросы — лучший сигнал о дырах в объяснении.
- Читает в основном с телефона, вопросы оставляет в GitHub Issues
  с меткой `непонятно`.
- Общение и текст книги — на русском.

## Если меняется решение

Любое новое решение по структуре, правилам или процессу записывай
в `DECISIONS.md` с датой и причиной. Если меняется оглавление —
сначала `PLAN.md`, потом `tools/book.py scaffold`.
