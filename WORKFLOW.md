# Как пишется и проверяется книга

## Главная идея

То, что можно проверить механически, проверяет скрипт. ИИ нужен там,
где требуется суждение. Автор проекта — настоящий читатель без знаний,
агенты отсеивают очевидные дыры до него.

## Порядок работы

Подглавы пишутся строго по порядку PLAN.md. Следующую подглаву
не начинают, пока предыдущая не в статусе `принято` или `нужен человек`
(во втором случае можно идти дальше, но вопрос автору обязателен).

## Цикл одной подглавы

```
1. АВТОР (prompts/author.md)
   Получает: RULES.md, PLAN.md, реестр терминов, тезисы и словари
   принятых глав, план этой подглавы.
   Пишет: текст подглавы, шапку (goals, introduces),
   новые записи в terms/terms.yaml.
   Статус → черновик.

2. СКРИПТ ТЕРМИНОВ (python3 tools/book.py check <id>)
   Проверяет: термины используются не раньше введения, аббревиатуры
   расшифрованы при каждом упоминании, нет неизвестных аббревиатур,
   defined_via введены раньше.
   Ошибки → обратно автору без участия ИИ-проверяющих.

3. ЧИТАТЕЛЬ-НОВИЧОК (prompts/reader.md)
   Получает ТОЛЬКО текст книги до этого места включительно,
   без шапок, реестра и плана.
   Пересказывает механизм своими словами, называет места, где
   пришлось догадываться, и слова, которые не объяснены.
   Оркестратор сравнивает пересказ с goals из шапки:
   расхождение = дыра в объяснении.

4. ФАКТЧЕКЕР (prompts/factchecker.md)
   С доступом к вебу. Проверяет числа, поля, версии, ссылки на RFC.

5. РЕДАКТОР (prompts/editor.md)
   Проверяет соблюдение RULES.md: аналогии, язык, «проблема → решение»,
   метки приёмов, глубина, скука.

Замечания 3–5 собираются в один список → АВТОР правит → снова с шага 2.
Статус → проверка, round += 1.

Всё чисто → статус принято, коммит.
round = 3 и не сошлось → статус «нужен человек», открыть issue
с меткой «нужен человек» и списком несошедшихся замечаний.
```

## Вопросы автора проекта (главный цикл)

1. Автор читает подглаву и открывает issue по шаблону «Непонятно»
   (метка `непонятно`), пишет как угодно.
2. ПРАВЩИК (prompts/fixer.md) определяет, какого звена объяснения
   не хватило: не введён термин, пропущен шаг механизма, слишком
   абстрактно, неясно «зачем».
3. Правит текст (и реестр, если нужен новый термин), прогоняет цикл
   со шага 2.
4. Отвечает в issue: что было непонятно и что изменено, со ссылкой
   на коммит. Закрывает issue.
5. Если правка затронула термин, используемый дальше, проверяет
   (`book.py check`) все последующие принятые подглавы.

Записи issues — материал для раздела «Что ломается»
и указателя по симптомам.

## Глава целиком

Когда все подглавы главы приняты, автор-агент дописывает в `index.md`
тезисы главы и словарь новых терминов (из реестра).

## Начало новой сессии

1. Прочитать CLAUDE.md и файлы по его списку.
2. `python3 tools/book.py status` и `python3 tools/book.py next`.
3. Проверить открытые issues с метками `непонятно` и `нужен человек`.
   Issues автора — приоритет выше новых подглав.
